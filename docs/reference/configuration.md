# Configuration

Runtime settings live in the repository `.env` file. The installer creates it from `.env.example` when needed.

## Main settings

```dotenv
CONTAINER_NAME=firstmate
DIND_CONTAINER_NAME=firstmate-dind
HERDR_SESSION=firstmate

DOCKER_VERSION=29
FIRSTMATE_REF=main
CODEX_VERSION=latest

GIT_USER_NAME=Your Name
GIT_USER_EMAIL=your-github-noreply@example.com
```

### Runtime names

`CONTAINER_NAME`
: Name of the Firstmate container.

`DIND_CONTAINER_NAME`
: Name of the isolated Docker-in-Docker container.

`HERDR_SESSION`
: Persistent Herdr session name used by `fmh connect`.

### Upstream versions

`DOCKER_VERSION`
: Docker major used both for the Docker CLI embedded in Firstmate and the DinD daemon.

`FIRSTMATE_REF`
: Git ref used when building the upstream Firstmate checkout into the image.

`CODEX_VERSION`
: Codex CLI version installed in the Firstmate image.

Pin these values when reproducible deployments are more important than automatically tracking upstream releases.

### Git identity

`GIT_USER_NAME` and `GIT_USER_EMAIL` configure the Git identity used by agents when they create commits.

## Persistent volume names

The defaults are:

```dotenv
FIRSTMATE_HOME_VOLUME=firstmate-homelab-home
DIND_DATA_VOLUME=firstmate-homelab-dind-data
DIND_CERTS_CA_VOLUME=firstmate-homelab-dind-certs-ca
DIND_CERTS_CLIENT_VOLUME=firstmate-homelab-dind-certs-client
```

`FIRSTMATE_HOME_VOLUME`
: Persistent `/home/node` containing authentication, Firstmate/Herdr state, projects, Treehouse worktrees and user-space tooling.

`DIND_DATA_VOLUME`
: Persistent `/var/lib/docker` for the isolated daemon, including images, BuildKit cache, containers and inner named volumes.

`DIND_CERTS_CA_VOLUME` and `DIND_CERTS_CLIENT_VOLUME`
: TLS material generated by the official DinD image.

Changing volume names effectively selects a different persistent installation. Keep the names stable if you expect data to survive upgrades or reinstalls.

## Global launcher configuration

The installer records the repository checkout path in:

```text
~/.config/firstmate-homelab/config
```

or below `$XDG_CONFIG_HOME` when that environment variable is set.

This is why `fmh` can operate the stack from any working directory.

## Runtime environment inside Firstmate

Important values injected by Compose include:

```text
FM_HOME=/home/node/.firstmate
FM_ROOT_OVERRIDE=/opt/firstmate
FM_BACKEND=herdr
CODEX_HOME=/home/node/.codex
DOCKER_HOST=tcp://localhost:2376
DOCKER_TLS_VERIFY=1
DOCKER_CERT_PATH=/certs/client
```

These are implementation settings and normally do not need to be changed by users.
